# TVCF 한국 광고 다운로더

TVCF 목록에서 한국 광고(`country_code=410`, `category_code=1`)만 찾아 기간 기준으로 다운로드하는 GUI 프로그램입니다.

## 실행

Python 3.10 이상을 권장합니다.

압축을 푼 뒤 `START.bat`을 실행하면 됩니다.

`START.bat` 파일 하나만 따로 전달해도 실행할 수 있습니다. 이 경우 `START.bat`이 있는 위치에 `TVCF_DOWN_0702` 폴더를 만들고 GitHub 저장소에서 최신 파일을 내려받은 뒤 실행합니다.

`START.bat`은 가능하면 자주 바뀌지 않도록 최소 부트스트랩 파일로 유지합니다. 실행할 때마다 Git 최신 버전 확인과 저장소 준비만 먼저 처리하고, 업데이트가 적용된 뒤의 실제 실행 절차는 `scripts\run_after_update.bat`으로 넘깁니다.

향후 `.venv`, `pip install`, Playwright, `bin` 도구 확인, GUI 실행 순서가 바뀌면 `START.bat`이 아니라 `scripts\run_after_update.bat`에서 관리합니다.

실행 과정은 다음과 같이 나뉩니다.

- Git 최신 버전 확인 및 자동 적용
- `.git`이 없는 폴더라면 Git 저장소 연결 및 최신 파일 가져오기
- `scripts\run_after_update.bat` 실행
- `.venv` 가상환경 생성
- `requirements.txt`가 바뀐 경우에만 `pip install -r requirements.txt` 실행
- Playwright Chromium 브라우저 설치
- `bin` 폴더의 `ffmpeg.exe`, `ffprobe.exe`, `yt-dlp.exe` 확인 및 자동 준비
- GUI 실행

다음 실행부터는 설치된 환경을 재사용합니다. Python이 설치되어 있지 않은 PC에서는 Python 3.10 이상을 먼저 설치해야 합니다.

`START.bat` 하나만 전달받은 PC에서는 Git for Windows도 설치되어 있어야 저장소를 자동으로 내려받을 수 있습니다.

## 자동 업데이트

`START.bat` 실행 시 자동으로 `git fetch` 후 업데이트가 있는지 확인합니다.

- 업데이트가 있으면 `git pull --ff-only`로 자동 적용합니다.
- 로컬 코드 수정이 있으면 덮어쓰지 않고 자동 업데이트를 건너뜁니다.
- zip으로 받은 폴더처럼 `.git` 정보가 없으면 Git 저장소를 연결하고 최신 파일을 가져옵니다. 기존 코드 파일은 `.update_backups` 폴더에 백업됩니다.
- 업데이트 후 `START.bat`은 재시작하지 않고, 새로 받아진 `scripts\run_after_update.bat`을 바로 실행합니다.
- 업데이트 후 `requirements.txt`가 바뀌어도 `scripts\run_after_update.bat`에서 패키지 설치 확인을 다시 실행합니다.

## 동작 방식

1. 선택한 기간과 날짜 기준에 맞춰 TVCF 영상 목록을 읽습니다. GUI에서는 `방영일`, `TVCF 업로드 날짜`로 표시됩니다.
2. 결과에서 한국 광고만 로컬에서 필터링합니다.
3. 목록은 Next.js Flight 데이터의 `results` JSON 배열을 우선 구조적으로 파싱하고, 실패하면 기존 레거시 파서로 한 번 더 시도합니다.
4. 상세 페이지의 Next.js 초기 데이터에서 HD/SD/mobile `.m3u8` 스트림을 먼저 찾습니다.
5. 스트림이 없으면 Playwright 네트워크 감시로 `.m3u8`을 다시 찾습니다.
6. 다운로드는 `yt-dlp`를 먼저 사용하고, 실패하거나 없으면 `ffmpeg`를 사용합니다. `ffmpeg`에는 HTTP 재연결 옵션을 넣어 중간 네트워크 끊김에 더 강하게 처리합니다.
7. 일시적 네트워크 오류, timeout, HTTP 429/5xx는 정책에 따라 재시도하고, HTTP 404는 재시도하지 않습니다.

## 저장 경로 유지

GUI에서 선택한 저장 폴더와 옵션은 `config.json`에 저장됩니다. 프로그램을 다시 열면 마지막 설정이 복원됩니다.

GUI의 `저장 폴더 열기` 버튼으로 현재 저장 위치를 Windows 탐색기에서 바로 열 수 있습니다.

## ffmpeg

앱은 `bin\ffmpeg.exe`를 자동으로 사용합니다. 파일이 없으면 BtbN FFmpeg-Builds의 최신 Windows release branch zip을 내려받고, 압축을 풀어 `bin\ffmpeg.exe`에 배치합니다.

FFmpeg 공식 사이트는 Windows 실행 파일을 직접 제공하지 않고, 컴파일된 패키지 배포처를 안내합니다. 이 앱은 자동 다운로드와 버전 확인이 쉬운 BtbN GitHub 최신 릴리스를 사용합니다.

## yt-dlp

TVCF의 일부 최신 영상은 TVCF 자체 스트림이 아니라 YouTube 원본 링크(`streams.urf`)로 연결됩니다. 이런 영상은 `yt-dlp`가 필요하며, 앱은 `bin\yt-dlp.exe`가 없으면 자동으로 내려받습니다.

## 기간 다운로드 팁

날짜 기준은 두 가지입니다.

- `방영일`: 광고 방영일 기준
- `TVCF 업로드 날짜`: TVCF 등록/업로드 날짜 기준

목록 페이지는 자동 탐색으로 동작합니다. 날짜 정렬 목록을 읽다가 선택한 기간보다 오래된 페이지에 도달하면 자동으로 멈춥니다.

다운로드 대상은 선택한 기간 안에서 시작일이 먼저 오도록 정렬됩니다. 예를 들어 `2026-06-19~2026-07-02`라면 `2026-06-19` 영상부터 다운로드합니다.

## 기존 파일과 중단 처리

다운로드할 파일이 이미 있으면 `ffprobe`로 정상 재생 가능한 MP4인지 검사합니다.

- 정상 파일: 다시 받지 않고 건너뜁니다.
- 손상 파일: 삭제 후 다시 다운로드합니다.
- 중단/실패 후 남은 임시 파일: 다음 다운로드 전에 자동 정리합니다.

GUI의 `작업 요약 / 중단 지점`에는 마지막 실행 조건과 현재 처리 중인 날짜/항목이 표시됩니다. 중단 후 앱을 다시 열어도 마지막 지점이 남아 있습니다.

목록의 `선택` 컬럼에서 재다운로드할 항목을 체크한 뒤 `체크 재다운로드` 버튼을 누르면 해당 항목이 목록 맨 뒤로 이동하고 상태가 `대기열에 다시 추가됨`으로 바뀝니다. 현재 다운로드가 진행 중이면 기존 작업이 끝난 뒤 이어서 재다운로드하고, 작업 중이 아니면 재다운로드 대기열을 바로 실행합니다.

`보류 일괄 재다운로드` 버튼을 누르면 체크하지 않아도 `오류`, `중단됨`, `보류` 상태인 항목을 자동으로 찾아 재다운로드 대기열에 추가합니다.

재다운로드는 먼저 기존 방식으로 한 번 재시도하고, 실패하면 상세 정보를 다시 조회한 뒤 ffmpeg 우선 방식으로 한 번 더 시도합니다.

## 다운로드 목록 필터와 검색

다운로드 목록은 상태 필터와 검색어를 동시에 적용할 수 있습니다.

- 상태 필터: 전체, 완료, 오류, 보류, 중단됨, 건너뜀, 다운로드 중
- 검색 대상: 날짜, 제목, TVCF ID, 상태, 저장 파일 경로

필터와 검색은 화면 표시만 바꾸며 내부 다운로드 대기열이나 작업 데이터는 삭제하지 않습니다.

## 다운로드 이력

다운로드 성공 또는 기존 정상 파일 건너뜀은 `download_history.json`에 TVCF ID 기준으로 기록됩니다.

이력에 같은 TVCF ID가 있고, 기록된 파일 경로가 실제로 존재하며 `ffprobe` 검사도 정상이면 저장 폴더나 파일명이 달라도 다시 다운로드하지 않고 `건너뜀`으로 표시합니다.

사용자가 `체크 재다운로드` 또는 `보류 일괄 재다운로드`로 명시적으로 재다운로드한 경우에는 이력이 있어도 다시 다운로드합니다.

이력 파일이 손상되어 읽을 수 없으면 `.broken_날짜.json`으로 백업하고 새 이력 파일을 만듭니다.

## 진행률과 병렬 다운로드

GUI는 현재 파일 진행률, 전체 진행률, 완료/오류/건너뜀 개수, 다운로드 속도, 예상 남은 시간을 표시합니다.

다운로드 옵션에서 병렬 개수를 1, 2, 3 중 선택할 수 있습니다. 기본값은 서버 부담을 줄이기 위해 1입니다.

`yt-dlp` 우선 다운로드와 Playwright fallback은 항상 켜진 상태로 동작하며 GUI에서는 따로 표시하지 않습니다.

화질 옵션에는 `가능한 최고화질`이 있으며, HD, SD, mobile, 기타 스트림 순서로 사용 가능한 가장 좋은 스트림을 선택합니다. YouTube 원본 URL은 `yt-dlp` 기본 최고 품질 선택을 사용합니다.

다운로드 완료 시 동작은 GUI의 드롭다운 3개로 설정합니다. 기본값은 모두 `안띄우기`, `안열기`, `안끄기`입니다.

- 알림창: `띄우기`를 선택한 경우에만 완료/오류/건너뜀 개수를 요약하는 GUI 알림이 뜹니다.
- 폴더: `열기`를 선택한 경우에만 작업 완료 후 저장 폴더를 Windows 탐색기로 엽니다.
- 전원: `끄기`를 선택한 경우에만 작업 완료 후 60초 지연 Windows 종료를 예약합니다. 중지 버튼으로 작업을 멈춘 경우에는 실행하지 않습니다.

## 도구 자동 갱신

`scripts\run_after_update.bat`의 환경 체크 단계에서 `yt-dlp.exe`와 `ffmpeg.exe`를 확인합니다.

- `yt-dlp.exe`는 7일 이상 최신 확인을 하지 않았으면 최신 파일로 다시 내려받습니다.
- `ffmpeg.exe`는 7일 이상 최신 확인을 하지 않았으면 BtbN FFmpeg-Builds 최신 릴리스와 비교하고, 새 빌드가 있으면 교체합니다.
- 갱신 확인에 실패해도 기존 실행 파일이 있으면 그대로 사용합니다.
- Git 업데이트 전 현재 HEAD를 기록하고, 업데이트 후 핵심 파일이 사라진 경우 이전 HEAD로 롤백을 시도합니다.

## 작업 기록과 오류 신고

실행마다 `logs\sessions`에 작업 기록이 JSON으로 저장됩니다. 각 영상의 성공, 건너뜀, 제외, 실패 상태와 파일 경로 또는 오류 로그 경로를 확인할 수 있습니다.

다운로드 실패는 `logs\errors`에 개별 케이스로 저장됩니다. 같은 오류마다 사람이 읽기 좋은 `.txt`와 이슈 업로드용 `.json`이 함께 생성됩니다.

GUI의 `기훈이한테 이르기` 버튼은 현재 다운로드 목록에서 오류 상태인 항목 전체를 모아 GitHub 이슈 하나로 업로드합니다. 이슈 본문은 추후 분석하기 쉽도록 원본 오류 JSON 중심으로 저장됩니다.

자동 이슈 업로드에는 프로젝트 폴더의 `github_issue_token.json` 또는 환경변수 `TVCF_GITHUB_TOKEN` / `GITHUB_TOKEN`이 필요합니다. `github_issue_token.example.json`을 참고해 `github_issue_token.json`을 만들면 됩니다.

`github_issue_token.json` 예시:

```json
{
  "token": "GitHub fine-grained token with issue read/write permission"
}
```

`github_issue_token.json`은 GitHub에 업로드되지 않습니다.
